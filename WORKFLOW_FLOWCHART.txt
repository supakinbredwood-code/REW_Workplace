================================================================================
REW WORKPLACE — CROSS-FUNCTIONAL FLOWCHART (SWIMLANE) ฉบับละเอียด
================================================================================
เอกสารนี้อธิบายการทำงานของระบบทั้งหมดในรูปแบบ Cross-Functional Flowchart
(Swimlane Diagram) เวอร์ชันข้อความ โดยแบ่งเป็น "เลน" (Lane) ตามผู้ที่รับผิดชอบ
ขั้นตอนนั้น ๆ อ่านจากบนลงล่างตามลูกศร | และ v แต่ละกล่องจะระบุชื่อเลนไว้ใน [ ]
พร้อมอ้างอิงไฟล์/ฟังก์ชันจริงในโค้ด เพื่อให้ตรวจสอบย้อนกลับไปที่ source ได้

หมายเหตุสถาปัตยกรรม:
- แอปนี้เป็น client-side ล้วน (ไม่มี backend / ไม่มีการเรียก API จริง)
- ข้อมูลหลัก (users, approvalRequests, chatMessages, warehouseZones ฯลฯ)
  เป็น in-memory JavaScript array/object ใน js/data/*.js → หายเมื่อ refresh หน้า
- มีเพียงค่าเดียวที่ persist ผ่าน localStorage คือ session (key
  "rewworkplace_session" เก็บ user.id) ดูฟังก์ชันใน js/services/authService.js

--------------------------------------------------------------------------------
LEGEND — คำจำกัดความของเลน (Swimlanes)
--------------------------------------------------------------------------------
[Employee]   ผู้ใช้ทั่วไป / พนักงาน — โต้ตอบกับหน้าจอผ่านการคลิก/พิมพ์
[Approver]   ผู้ใช้ที่มี role === "approver" — พนักงานที่มีสิทธิ์อนุมัติคำขอ
[Admin]      ผู้ใช้ที่มี isAdmin === true — จัดการ Organization และ Clock-in Zone
[Device]     Browser API ของอุปกรณ์ (เช่น navigator.geolocation, FileReader)
[UI]         Component layer (js/components/*.js) — จัดการ DOM, event, render
[Service]    Business logic layer (js/services/*.js) — กฎเกณฑ์ของระบบ
[Data]       Data layer (js/data/*.js in-memory) + localStorage (session)

--------------------------------------------------------------------------------
สารบัญ
--------------------------------------------------------------------------------
1. App Bootstrap & Session Restore
2. Login
3. Clock In / Clock Out (พร้อมตรวจสอบพิกัด GPS)
4. Chat — เปิดแชทและส่งข้อความ
5. Approval — พนักงานสร้างคำขอ (Request OT / Request Item)
6. Approval — ผู้อนุมัติพิจารณาคำขอ (Approve / Reject)
7. Profile — ดูและแก้ไขโปรไฟล์ (รวมเปลี่ยนรูป)
8. Admin — ตั้งค่า Organization (ตำแหน่ง/คลัง/สายอนุมัติ)
9. Admin — ตั้งค่า Clock-in Zone (พิกัด GPS และรัศมี)
10. Logout
11. Bottom Navigation (การสลับหน้าจอหลัก)

สรุปความสัมพันธ์ระหว่าง Flow (Cross-Flow Dependencies)
================================================================================
- Flow 8 (Admin ตั้งค่า Approver) ------> เป็นอินพุตของ Flow 5 (user.approverId
  ถูกใช้ตอนสร้างคำขอใหม่)
- Flow 8 (Admin ตั้งค่า Warehouse) -----> เป็นอินพุตของ Flow 3 (user.warehouse
  ใช้หา zone ที่ต้องตรวจสอบ)
- Flow 9 (Admin ตั้งค่า Zone lat/lng/radius) --> เป็นอินพุตของ Flow 3
  (checkZone() เทียบระยะทางจริงกับค่านี้)
- Flow 5 (พนักงานสร้างคำขอ) ------------> ปรากฏใน Flow 6 (ผู้อนุมัติเห็นและ
  กดอนุมัติ/ปฏิเสธ) เพราะทั้งคู่อ่าน/เขียน array approvalRequests[] ร่วมกัน
- Flow 2 (Login) ----------------------> เป็นจุดเริ่มของทุก Flow อื่น (ต้องมี
  currentUser ก่อนเสมอ มิฉะนั้น service หลายตัว return null/ทำงานไม่ได้)
